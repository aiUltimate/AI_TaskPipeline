AI Modular Pipeline – Browser Demo

Two fully transparent pipelines in one HTML file: a weather pipeline and a web-page analyzer pipeline, both exposing every intermediate JSON stage.

Live node graph JSON-in → JSON-out Provider-agnostic

Each box below is a node. Nodes are pure functions that take one JSON object and return a new one. The browser UI shows you exactly what flows through each step so you can debug, swap nodes, and grow from toy examples to complex products.

Weather pipeline: fully local (mocked) Web analyzer: real HTML fetch + optional free LLM (Hugging Face)

Pipeline Overview

Both pipelines follow the same pattern: normalize messy input → build a provider-agnostic spec → adapt → execute → normalize output → render.

1 Input – free-form text from you.
2 Cleaning / Spec – we normalize into a typed JSON spec.
3 Adapter – we shape the spec for a concrete API or tool.
4 Execution – call the provider (mock, API, or LLM).
5 Formatter – normalize provider output back into a clean JSON shape.
6 UI Renderer – show the human-readable results plus the raw JSON.

Weather Pipeline (Mocked)

Example of a numeric pipeline: we turn a city name into a simple forecast with derived stats and comparison to last run.
Nodes: 6 External calls: 0 (mock)
Node 1 – Location Spec
User text → LocationSpec
/nodes/location-spec

Parses your free-form location text into a structured object with city, country guess, and units. This is the “normalized” view of your input.

Node 2 – Weather Request
LocationSpec → WeatherRequest
/nodes/weather-request

Converts the location spec into a provider-agnostic “request” structure. In a real system this would map to Open-Meteo or any other weather provider. 

{}
Node 3 – Forecast (Mock)

Web Analyzer Pipeline

Turns a natural language request with a URL into a list of top links and a natural language summary (mock or Hugging Face).
Nodes: 6 Uses: DOMParser + optional free LLM

Model: facebook/bart-large-cnn. The request is built as a normal JSON payload; you can inspect it below.

Node 1 – Raw Text Input
User text → RawTextInput
/nodes/web-input

Captures the exact text you typed. No interpretation, no magic. This is the “raw” entry point to the pipeline. 

{}
Node 2 – Prompt Cleaner / URL Extractor
RawTextInput → PromptDraft
/nodes/web-prompt-draft

Normalizes whitespace and extracts the first URL it finds with a simple regex. That URL is what the rest of the pipeline uses. 

{}
Node 3 – Web Fetch
PromptDraft → FetchedPage
/nodes/web-fetch

Fetches the HTML for the detected URL. If CORS blocks the request, it falls back to a public proxy (api.allorigins.win). 

{}
Node 4 – HTML → Links Extractor
FetchedPage → ExtractedLinks
/nodes/web-links

Uses the browser’s DOMParser to turn raw HTML into a document, then walks <a> tags to collect clickable links and normalize them to absolute URLs. 

{}
Node 5 – Top Links Selector
ExtractedLinks → TopLinks
/nodes/web-top-links

Ranks links with a simple heuristic (longer titles first) and takes the top N. In a more advanced system this would be a proper ranking node. 

{}
Node 6 – Summarizer (AI / Mock)
TopLinks → SummaryOutput
/nodes/web-summary

Builds a plain-text prompt listing the links and either: (a) calls Hugging Face with your token or (b) uses a local mock summarizer.

Run the pipeline to see a summary here. If you don’t provide a Hugging Face token, you’ll see a mock summary built locally.

This file is intentionally “flat”: HTML + CSS + JS only. In a larger project, each node would live in its own module and pipelines would be declared via configuration, but the core idea remains the same: observable, swappable, JSON-typed stages from input to output.
